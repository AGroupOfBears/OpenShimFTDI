# OpenShimFTDI ECU Simulator Implementation Specification

## Supported Modes
1. **sim**: Pure software ECU operating behind the helper abstraction.
2. **ipc**: Hardware mediation connecting to physical OpenPort 2.0.
3. **ipc-sim**: Hybrid. Hardware OpenPort is commanded to configure filters and emit wakeups safely, but all RX frames are simulated. Hardware ECU responses are suppressed/logged to prevent loopback contamination and destruct-traffic mirroring.

## TASK 1 \& 2 — CONNECTION / INIT PATH
* **OBSERVED**: TuneECU loops connection retries alternating between two initialization modes via `ISOMain.mECU >> 1 != (ISORead.iRetry & 1)` logic.
* **CONFIRMED**: **KWP Fast Init (`KWPInit`)**: Used primarily for Keihin architectures (`ISOMain.KWP = true`). Executes a 200ms `0` break, writes a `0x00` burst at 360 baud (measuring ~25ms low), switches to 10400 bps, and issues `0x81` (StartCommunication). 
* **CONFIRMED**: **5-Baud Init (`Initialization(51)`)**: Bit-bangs `0x33` over UART breaks (196ms per bit) then proceeds.
* **CONFIRMED**: For Keihin Map 20417, `KWPInit` is the targeted connection protocol. The `StartCommunication` response must be `0xC1 0xDA 0x8F` to be successfully interpreted into `ISOMain.KWP = true` logic and unlock the seed flow. 

## TASK 3 — SECURITY ACCESS
* **CONFIRMED**: After `0xC1`, state enters `eMode.MODE_SEED`.
* **CONFIRMED**: TuneECU requests Diagnostic Seed using `0x27 0x03`. The ECU must reply with `0x67 0x03 <SeedHi> <SeedLo>`.
* **CONFIRMED**: Key Algorithm executes: `Key = (Seed * (KEYW_Final ^ ModeConst)) & 0xFFFF`.
* **CONFIRMED**: `KEYW_Final` resolves from `ulong 11123772655450801483uL` bit-shifts scaling to `53504` (`0xD100`).
* **CONFIRMED**: For Diagnostic Session (`AM=3`/`AM=5`), `ModeConst = 40014`. The diagnostic key computes as `Key = (Seed * 29330) & 0xFFFF`.
* **CONFIRMED**: For Flashing Session (`mFlash=true`), `ModeConst = 48689`. The programming key computes as `Key = (Seed * 15265) & 0xFFFF`.
* **CONFIRMED**: TuneECU transmits the Key via `0x27 0x04 <KeyHi> <KeyLo>`. (Or `0x27 0x06` for Flash blocks).

## TASK 4 — AUTOMATIC IDENTIFICATION
* **CONFIRMED**: TuneECU identifies Keihin maps directly via `ReadDataByLocalIdentifier` (`0x1A`).
* **CONFIRMED**: `0x1A 01` retrieves VIN string.
* **CONFIRMED**: `0x1A 02` retrieves ECU hardware Type (used by `IMap.CheckMapID` to populate `TypTable=40`).
* **CONFIRMED**: `0x1A 05` retrieves `baseMap`.
* **CONFIRMED**: `0x1A 20` retrieves secondary map checksum/headers. 
* **OBSERVED**: Finishing `0x1A 20` properly transitions the interface into `eMode.MODE_READ_SENSORS` or Map Block Read.

## TASK 6 — MAP READ 
* **CONFIRMED**: Triggered via `eMode.MODE_READ_MEM` routing through `SendReadData()`.
* **CONFIRMED**: Issues `0x23` (ReadMemoryByAddress) with explicit 6-byte query: `[0x23, addrHi, addrMid, addrLo, size, 0x00]`.
* **CONFIRMED**: `size` is driven by `ISOMain.sBloc`. For Keihin Maps (`ISOMain._KTM == true`), block chunking operates strictly in `128` byte iterations.

## MEMORY MODEL (TASK 8)
* The 20417Map.hex binary must be decompressed locally mapping exact offset windows from `0x50000` outwards mirroring `IMap.addrTable` splits. Changes generated by internal editing (e.g. `0x5061C` = 14200) write natively overlapping this array copy and serve directly to `0x23` network chunk asks. Destructive edits are cached purely in simulation layers holding baseline original files isolated from changes.

### Unresolved Blockers (Stop Condition Enforced)

Simulator specification is NOT yet sufficiently resolved for implementation.

**Exact Remaining Blockers:**
1. **Live Diagnostics (TASK 5)**: I have not yet mapped the exhaustive iteration byte stream from `ISensor.DataSensorReceive`. The `SendSensorQuery` / `SendPidQuery` lists polling array IDs (`readSensor`) requiring exact byte layouts scaling TPS, Coolant, and RPM to fool TuneECU into steady green connectivity.
2. **Map Write Pathing (TASK 7)**: The Erase / Block Transfer / Download confirmation bytes (`eMode.MODE_DOWNLOAD`, `MODE_START_PROG`, etc) and `RequestDownload` structures (`34`, `36`, `31`) are not completely traced for Keihin flashing unlocks. We lack the checksum calculation byte required at transfer completion.
3. **IPC Backend Hybrid Protocol (TASK 9 & 10)**: Strict JSON layout defining the inter-process commands mediating state switches, baud rate swaps, filtering commands, and OpenPort clearing between Shim and Helper isn't drafted to handle dynamic KWP suppression semantics yet.
